 # GRaMC – Grain Reconstruction and Multi-stage Cleaning

 Heuristic Grain Reconstruction and Microstructural Restoration for EBSD

 **Note:** GRaMC is designed to be used in tandem with **MAPClean** (Microstructurally Adaptive Pixel-Level Cleaning), the primary software associated with Subbaraman et al. (in prep). While **MAPClean** handles pixel-level noise removal and data restoration, **GRaMC** takes the cleaned output and applies **grain-level reconstruction logic** to produce robust grain sets for analysis.

 This version moves beyond standard MTEX grain reconstruction by incorporating phase splitting, removal of zero-GOS grains, crystallographic twin merging, pixel-level reorientation of merged daughter grains, and optional area-based population filtering. It is designed for complex geological materials, especially twinned feldspars such as **Anorthite-rich Plagioclase**.

 ## Key Features
 * **Phase Splitting:** Automatically splits MAPClean outputs into phase-specific `.ctf` files so grain reconstruction can be performed on a single mineral population at a time.
 * **Multi-Stage Reconstruction:** Checkpointed workflow allowing users to inspect EBSD and grain objects at every major stage of reconstruction.
 * **Initial Grain Reconstruction:** Reconstructs grains using a fixed misorientation threshold and removes sub-resolution noise grains below a minimum pixel count.
 * **GOS = 0 Grain Removal:** Identifies grains with zero Grain Orientation Spread and removes them by resetting their pixels to `notIndexed`, followed by grain recalculation.
 * **Twin Boundary Merging:** Automatically detects and merges grains separated by specific twin laws. The current version is pre-configured for **Anorthite** laws: **Albite, Pericline, Carlsbad, Manebach, Baveno-Right, Baveno-Left, Ala_A, and Ala_B**.
 * **Pixel-Level Reorientation After Merge:** After grain-level twin merging, daughter-grain EBSD pixels are rotated into the parent reference frame so the EBSD object remains physically consistent with the merged grain structure.
 * **Grain Size Diagnostics:** Exports a `log10(area)` histogram and a matching colour-coded grain map so users can visually determine a suitable size threshold for their target population.
 * **Area-Based Population Filtering:** Applies a user-defined, sample-specific `log10(area)` threshold to remove unwanted small-grain populations such as microlites before final grain statistics.
 * **Advanced Property Calculation:** Automatically recalculates **Grain Orientation Spread (GOS)** and **Mean Orientations** during merging events using area-weighted logic.

 ## Requirements
 * **MATLAB** (Tested on 2024b)
 * **MTEX Toolbox** (Tested on v 6.0.0)
 * **Parallel Computing Toolbox** — used during pixel-level daughter-grain reorientation after twin merging

 ## Installation & Setup
 GRaMC is designed to share a workspace with **MAPClean**.

 1. Download `GRaMC.m`.
 2. Place it in the **same folder** as `MAPClean.m`.
 3. No manual file copying is required; GRaMC will automatically read the cleaned `.ctf` files generated by MAPClean in the `DataFiles` folder.

 ## Usage
 1. Open `GRaMC.m`.
 2. Set the **Stage Control Flags** to determine which steps to run:
 ```matlab
 runPhaseSplit  = true;   % Create / refresh phase-specific .ctf files
 run_initial    = true;   % Initial reconstruction
 run_gosClean   = true;   % Remove GOS = 0 grains
 run_twinMerge  = true;   % Merge twins and update EBSD
 run_sizeThresh = true;   % Plot size-distribution diagnostics
 run_areaFilter = true;   % Apply area threshold
 run_Final      = true;   % Save final output
 ```
 3. Set any sample-specific `log10(area)` thresholds in the parameter section.
 4. Run the script.
 5. Final output files (`*_finalGrains.mat`) are saved in the `checkpoints` directory, ready for downstream analysis (e.g., using **GRaFT**).

 ## Workflow Details
 1. **Phase Splitting:** The full MAPClean output is split into phase-specific EBSD maps. GRaMC then loads the target phase (currently configured for **Anorthite**) for grain reconstruction.
 2. **Initial Reconstruction:** Grains are calculated from pixel data using a misorientation threshold (default `10°`). Small noise grains are immediately removed using a minimum pixel-count criterion.
 3. **GOS = 0 Cleanup:** Grains with zero Grain Orientation Spread are identified and removed by resetting their pixels to `notIndexed`, followed by a fresh grain reconstruction.
 4. **Twin Merging:** Child grains sharing a valid twin boundary are merged into a single parent grain to reconstruct the original crystal morphology.
 5. **Pixel Reorientation:** After merging, daughter-grain pixels are rotated into the parent reference frame so the EBSD data remain consistent with the merged grain topology.
 6. **Size Diagnostics:** A `log10(area)` histogram and a matching colour-coded grain map are exported to help the user identify an appropriate grain-size threshold.
 7. **Area Filtering:** A sample-specific `log10(area)` threshold is applied to remove unwanted small-grain populations before final statistics or downstream texture analysis.

 ## Parameters

 | Parameter | Default | Description |
 | :--- | :--- | :--- |
 | `grainThreshold` | `10°` | Misorientation angle threshold for defining grain boundaries. |
 | `minPixelsGrains` | `5` | Minimum number of pixels required to constitute a valid grain during initial reconstruction. |
 | `binsPerDecade` | `10` | Number of histogram bins between `10^x` and `10^(x+1)` for the grain-size diagnostic plots. |
 | `logAreaThresh(sample)` | user-defined | Sample-specific `log10(area)` threshold used for final area-based grain filtering. |
 | `exportRes` | `300 dpi` | Resolution for exported PNG maps. |

 ## Directory Structure
 To ensure data flows automatically between stages, your folder should look like this:

 ```text
 My_EBSD_Project/
 ├── DataFiles/          # [Input] *_clean.ctf files and phase-specific .ctf files
 ├── checkpoints/        # [Shared] Auto-generated intermediate saves
 ├── GRaMC/              # [Auto] GRaMC figure outputs by sample
 ├── MAPClean.m          # (Stage 1) Pixel-level cleaning
 ├── GRaMC.m             # (Stage 2) This script
 └── GRaFT.m             # (Stage 3) Texture analysis
 ```

 ## The MAPClean Ecosystem
 MAPClean is the first step in a modular three-stage pipeline for EBSD analysis.
 1. **MAPClean:** Pixel-level noise removal and data restoration. [Link to Repo]
 2. **GRaMC:** Grain reconstruction, GOS-based cleanup, twin merging, and area-based population filtering.
